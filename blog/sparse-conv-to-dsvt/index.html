01 SPARSITY

点云为什么
天生稀疏？

LiDAR 发射激光，收到的只是物体表面被命中的离散回波。空中没有连续纹理，遮挡之后也没有像素；把它投到 BEV 网格，大多数格子自然为空。

96.7%

EMPTY / 全部网格

稀疏率ρ = 1 − Nactive / (H × W)= 1 − 4200 / (360 × 360)= 0.9676
  • Surface只照亮物体表面
  • Occlusion遮挡后没有回波
  • Tiny scale目标相对场景很小
  • Scattering回波离散、分布不均
关键直觉图像把“每个位置”当数据；点云把“有回波的位置”当数据。算法若仍为整张网格付费，绝大多数算力都花在空白处。
02 DILATION

一个 3×3 卷积，
怎样污染空白？

标准卷积输出的是“卷积核覆盖范围内的响应”。只要一个非零输入落进 3×3 邻域，它周围最多 9 个位置都可能变成非零。下一层再从这些新位置继续扩散。

03 SPARSE CONVOLUTION

第一代答案：
只在 active sites 上卷积

稀疏卷积不再保存完整致密张量，而是保存坐标 C 与特征 F；坐标映射决定哪些输入、权重和输出真正相遇。

Regular Sparse Conv

输出坐标可以扩张，适合下采样和建立新激活位置。

Submanifold Conv

输出坐标严格复用输入 active sites，阻止“submanifold dilation”。

04 TRANSFORMER

第二代答案：
把 voxel 当作 token

注意力天然在 token 列表上运算，不要求每个空间位置都有值；并且一次交互就能建立远距离关系。困难从“如何卷积”变成了“如何把数量不等的稀疏 token 整理成 GPU 喜欢的规则批次”。

WHY SINGLE STRIDE?

目标已经很小，
别再把它缩没。

在约 150 m × 150 m 的 Waymo 场景里，汽车只有约 4 m 长；映射到 600 × 600 网格也不过十几像素。Transformer 已能扩大感受野，DSVT 因此在 X/Y 平面维持 single stride，把小目标的空间细节留住。

06 VOXELS → TOKENS

最关键的一步：
不等长窗口如何并行？

每个窗口里的非空 voxel 数 N 不同。全 padding 浪费，逐窗循环又慢。DSVT 的解法是：每窗按稀疏度动态分配若干个固定长度 τ 的 set，然后把全场景所有 set 堆成一个 batch。

SLIDE EXAMPLEwindow_shape = [30, 30, 1]shift_list = [15, 15, 0]size_win_x = 360 / 30 = 12size_win_y = 360 / 30 = 12max slots = 13 × 13 × 2 = 338
DYNAMIC SET PARTITION

窗口越密，
分到的 set 越多。

① set 数量S = ceil(N / τ)
② 每个 set 的第 k 个索引qjk = floor(((jτ+k)/(Sτ)) · N)
③ GatherFj, Oj = INDEX(V, Qj, D)

公式②把 N 个排序后的 voxel 均匀采成 τ 个位置。除不尽时会重复少量索引，重复项在 attention 中用 mask 屏蔽。

这里第一个维度 2 不是 batch，而是同一批 voxel 的 X-axis 与 Y-axis 两种排序分组；这一点与官方实现的 set_voxel_inds 形状一致。

07 ROTATED SETS

第一次沿 X 排，
第二次沿 Y 排。

固定 set 内做 attention 会形成信息孤岛。DSVT 不改变 set 长度，只改变 voxel 的排序主轴：相邻层重分组后，上一层被隔开的 voxel 会在下一层进入同一 set。

Vl = MHSA(INDEX(Vl−1, Q, Dx) + PE)Vl+1 = MHSA(INDEX(Vl, Q, Dy) + PE)

Rotated set 解决窗内的跨 set 传播；两层合成一个 DSVT Block。

INTRA-WINDOW

Rotated set

同一窗口内，X / Y 主序交替，打通 set 边界。

INTER-WINDOW

Shift / hybrid window

相邻 block 改窗口边界与尺寸，打通 window 边界并平衡速度。

不要混淆旋转的是 set 内排序轴；位移的是 window 边界。前者完成窗内通信，后者完成跨窗通信。

把整条逻辑压成 8 句话

  1. 01LiDAR 只返回表面回波，BEV 网格约 96.7% 为空。
  2. 02普通卷积让 active sites 向空白区膨胀，结构和计算量一起变糊。
  3. 03稀疏卷积只处理有效映射，但坐标规则与定制 CUDA 增加部署成本。
  4. 04Transformer 把非空 voxel 直接当 token，天然适合长程关系。
  5. 05Single stride 保留 X/Y 分辨率，避免小目标在下采样中消失。
  6. 06动态稀疏窗口把每窗 N 个 voxel 整成若干个固定 τ 长度的 set。
  7. 07X/Y rotated sets 负责窗内通信，shift/hybrid windows 负责跨窗通信。
  8. 08注意力式 3D 池化补齐 Z 维下采样，整条 backbone 可用标准算子部署。
09 THE VERDICT
Effective≠Elegant
ResNet

F(x) + x

一个 shortcut 同时改善优化、梯度传播与深层网络退化。原则简单，后果深远。

PointNet

MLP + MAX

共享逐点变换加对称聚合，一句话解决点集的排列不变性。

DSVT

一串精确的 tricks

  • 固定窗口里 token 数不同 → 动态切 set
  • set 要等长 → 重复索引再 mask
  • set 彼此隔绝 → X/Y rotated ordering
  • window 彼此隔绝 → shift + hybrid shapes
  • 3D 下采样不稳 → max query + attention pooling
  • 部署要快 → 把一切整理成标准算子
DSVT 的美感不在“一个简单原则解释全部”，而在“把每一个工程裂缝都补到能并行、能部署、能保持精度”。这是一种系统工程的完整，却不是 ResNet / PointNet 那种令人拍案的概念简洁。

因此它很强，也明显有 trick 感。超参数 τ、两种排序、两类窗口变化、重复 token mask 与额外 pooling 让读者必须记住多个机制；任何单独一项都不构成新的基本抽象。DSVT 更像对“稀疏、局部、并行、跨域、部署”五个约束的联合求解，而不是从一个第一性原理自然长出的架构。这不削弱它的实用价值，却解释了为什么它不如 ResNet 或 PointNet 好记、好迁移、好复述。
